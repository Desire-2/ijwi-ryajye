# Ijwi Ryajye

**"The Voice of Crops"** — an agricultural communication & commerce platform for
Rwanda. Farmers, buyers, cooperatives, logistics providers and extension
officers trade produce, negotiate offers, chat in groups, follow market prices,
receive weather advisories, and settle payments through a double-entry wallet.

## Repository layout

```
backend/        Flask REST API + WebSocket realtime server + Celery workers
  app/          application factory, models, services, api modules, tasks
  migrations/   (generated by Flask-Migrate when schema changes)
  scripts/      seed_dev.py (demo data), smoke_e2e.py (full-flow check)
mobile/         Flutter/Dart client (offline-first: sqflite outbox + sync engine)
docs/           database ERD, API reference, business rules, deployment guide
deploy/         Dockerfiles, nginx config
tests/          unit / integration / failure-mode / e2e pytest suites
docker-compose.yml  postgres + redis + api + realtime + worker + beat + nginx
Makefile        common developer commands
```

## Quick start (local development)

Prerequisites: Python 3.10+, PostgreSQL 14+ (or use docker-compose), Redis optional.

```bash
# 1. Backend
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp ../.env.example .env            # adjust DATABASE_URL if needed

python3 scripts/seed_dev.py        # creates schema + demo data (idempotent)
python3 wsgi.py                    # REST API on :5000 (includes /socket.io)
```

Demo accounts (all seeded): `claudine / farmer123` (farmer),
`jeanbosco / buyer1234` (buyer), `eric / logistics1` (courier),
`admin / admin12345` (platform admin).

```bash
# 2. Full-flow smoke test against the dev DB
python3 scripts/smoke_e2e.py

# 3. Test suite (uses an isolated ijwi_test database)
cd .. && make test
```

## Mobile app

```bash
cd mobile
flutter pub get
flutter run --dart-define=API_BASE_URL=http://<your-host>:5000/api/v1 \
            --dart-define=REALTIME_URL=http://<your-host>:5000
```

The client is offline-first: mutations are queued in a local SQLite outbox with
`client_op_id` idempotency keys and pushed via `/sync/push`; collections are
cached and refreshed incrementally via `/sync/pull`.

## Key design decisions

- **Money is integer minor units** (100 minor = 1 RWF) everywhere — API,
  DB, ledger, mobile display helpers.
- **Append-only wallet ledger** with idempotency keys; balances are derived.
- **Payment webhooks** are HMAC-SHA256 signed over `{timestamp}.{body}`;
  replaying the same `event_id` is idempotent.
- **Offer negotiation state machine**: PENDING → ACCEPTED / REJECTED /
  COUNTERED / WITHDRAWN / EXPIRED; accepting creates the Order.
- **Auction anti-sniping**: bids inside the final window extend the auction.
- **Soft deletes** (`deleted_at`) on user-visible entities.
- ~205 routes under `/api/v1`, all documented in `docs/api.md`.
- Realtime rooms: `user:{id}`, `conversation:{id}`, `product:{id}`, `alerts`;
  socket handshake authenticates with the JWT access token.
